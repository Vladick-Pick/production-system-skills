# Как развивать набор

## Сначала определить дефект поведения

Изменение одного из четырёх скиллов должно отвечать на конкретный наблюдаемый сбой агента:

- неправильно определяет объект;
- смешивает процесс и действие;
- превращает документ в источник истины;
- не находит исключения;
- не умеет просчитать влияние;
- выпускает схему без связи с версией модели.

Не добавлять инструкции «на всякий случай».

Пятый скилл не добавлять без отдельного решения владельца о новой ответственности, которую нельзя корректно включить в существующие четыре.

## Порядок работы

1. Создать ветку codex/<краткое-название>.
2. Добавить или изменить проверочный сценарий в scripts/forward_test_fixtures.py.
3. Изменить минимальное число скиллов.
4. Проверить метаданные, ссылки и сценарии.
5. После изменения общего контракта выполнить python3 scripts/sync_references.py.
6. Обновить docs/SKILL-MAP.md, если изменились триггер, результат или маршрутизация.
7. Показать, какой прежний сбой теперь предотвращён.

## Обновление шаблона

1. Изменить канонический Google Sheets-шаблон отдельным принятым решением.
2. Экспортировать его в `templates/production-system-model-template-<version>.xlsx`.
3. Обновить `templates/template-manifest.yaml` и ссылки на новую версию.
4. Запустить синхронизацию references и полный валидатор.
5. Проверить, что в XLSX остались ровно объявленные листы, отсутствуют макросы и внешние бинарные связи.

Шаблон, язык и метаонтология меняются согласованно. Нельзя молча добавить столбец в таблицу и оставить четыре скилла на старом контракте.

## Требования к скиллу

Каждая папка содержит:

~~~text
skill-name/
  SKILL.md
  agents/openai.yaml
  references/   только при реальной необходимости
  scripts/      только для повторяемой детерминированной операции
  assets/       только для артефактов результата
~~~

Описание в frontmatter должно сообщать и функцию, и условия запуска. Триггеры не прятать только в тело: оно загружается после выбора скилла.

Корневые файлы references являются редактируемым источником. Одноимённые файлы внутри каждого скилла — синхронизированные копии для самостоятельной установки.

## Проверка на реальных задачах

Сложный скилл проверять на чистом контексте. Агенту передавать сам скилл и обычный пользовательский запрос, но не ожидаемый ответ и не диагноз предполагаемой ошибки.

Хороший тест доказывает переносимость метода, а не способность повторить подсказанный результат.
