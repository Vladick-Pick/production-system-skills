# Паспорт пакета методологии и Agent Skills

## Зачем существует этот контур

Мы выпускаем публичный версионируемый компонент платформенного контура: методологию, четыре Agent Skills, табличный шаблон, миграции и проверки для работы с моделью производственной системы.

Назначение и граница текущего компонента принадлежат [`docs/PACKAGE-SCOPE.md`](docs/PACKAGE-SCOPE.md). Полный продуктовый замысел принадлежит репозиторию платформы и намеренно не дублируется здесь; совместимый указатель сохранён в [`docs/PROJECT-INTENT.md`](docs/PROJECT-INTENT.md).

## Граница

- Текущий репозиторий реализует публичный семантико-методологический компонент: язык, agent harness, четыре скилла, каноническую табличную модель, миграции и проверки.
- Репозиторий не является программной платформой, постоянным резидентным контуром наблюдения или готовой системой исполнения.

## Текущее состояние

- Стабильный релиз — **v0.3**. Его точные артефакты и Google Sheets-шаблон зафиксированы в [манифесте](templates/template-manifest.yaml), а продуктовые изменения — в [release notes](docs/RELEASE-NOTES-v0.3.md).
- V0.2 сохранена как точка отката и историческая основа миграции, но не является текущей версией продукта.
- Активного плана следующего релиза сейчас нет. Единственный источник рабочего статуса — [индекс планов](plans/README.md).
- Новые наблюдения после v0.3 являются кандидатами следующего релиза, пока владелец не примет их и не откроет активный план. Нельзя заранее называть такой кандидат частью v0.4.
- Продуктовые решения платформы не образуют здесь параллельный backlog. Они входят в пакет только через принятый план совместимого выпуска.

## Ответственность

- Владелец решений и приёмки текущего пакета — Владислав Богдан.
- Агент репозитория исследует, проектирует, реализует и проверяет системные релизные пакеты, но не принимает продуктовую или бизнес-истину вместо владельца.
- При неизвестном владельце конкретного нового решения агент фиксирует `unknown`, а не назначает его по догадке.

## Минимальный маршрут новой сессии

1. Прочитать ближайший `AGENTS.md`.
2. Прочитать этот паспорт.
3. Для границы компонента или нового релиза прочитать [docs/PACKAGE-SCOPE.md](docs/PACKAGE-SCOPE.md).
4. Проверить [plans/README.md](plans/README.md): есть ли один активный план и что именно сейчас разрешено делать.
5. Затем читать только относящиеся к задаче `README`, architecture, references, skill, schema, script или release artifact.

Если `AGENTS.md`, паспорт, package scope, manifest и индекс планов расходятся, агент останавливает изменение, показывает конфликт и не выбирает удобную версию молча.

## Условия пересмотра паспорта

Паспорт обновляется, когда меняются граница продукта, владелец решения, стабильный релиз, источник истины или текущая стадия жизненного цикла. Детальная методология, исторические решения и задачи не копируются сюда: они остаются у своих владельцев.
