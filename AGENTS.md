# Контракт работы с репозиторием

## Назначение

Репозиторий содержит ровно четыре публичных русскоязычных скилла:

1. resolve-model-element;
2. model-production-system;
3. maintain-production-system;
4. audit-production-system.

Не добавлять управляющий business-ontology, служебные резидентные навыки или отдельные навыки источников без нового явного решения владельца репозитория.

## Первый просмотр

Перед изменением прочитать:

1. README.md;
2. docs/ARCHITECTURE.md;
3. references/LANGUAGE.md;
4. references/METAONTOLOGY.md;
5. references/TEMPLATE-CONTRACT.md;
6. templates/template-manifest.yaml;
7. затрагиваемый SKILL.md.

При изменении проекций дополнительно прочитать references/PROJECTION-CONTRACT.md.

После изменения любого корневого reference выполнить python3 scripts/sync_references.py. Копии внутри папок скиллов генерируются для самодостаточной установки и не редактируются вручную.

XLSX в templates является версионным экспортом канонического Google Sheets-шаблона. Не редактировать бинарный снимок вручную: обновлять экспортом из spreadsheet_id, затем обновлять version, exported_at и sha256 в template-manifest.yaml.

## Источники методологии

- Актуальны только reference-файлы этого репозитория и явно принятые решения владельца.
- Не использовать установленный локально старый business-ontology как источник требований.
- Не переносить скиллы из прежнего репозитория по сходству названий.
- Если reference-файлы конфликтуют, остановить изменение и показать конфликт.

## Правила

- Один скилл — один основной проверяемый результат.
- В YAML frontmatter использовать только name и description.
- Писать пользовательский текст и инструкции на русском языке; технические идентификаторы сохранять в kebab-case.
- Не дублировать язык в скиллах: ссылаться на общий контракт.
- Не добавлять новый элемент модели до семантического допуска.
- Не смешивать живую производственную систему, её модель, технологический кит, систему исполнения и производные представления.
- Не включать приватные данные, токены, закрытые ссылки и внутренние материалы компаний.
- Разрешён только явно объявленный публичный Google Sheets-шаблон из templates/template-manifest.yaml; новые Google Docs/Sheets-ссылки требуют отдельного решения владельца и проверки доступа.
- Не выдавать учебный пример за принятую истину.

## Проверка

Перед коммитом выполнить:

~~~bash
python3 scripts/validate_repository.py
python3 scripts/forward_test_fixtures.py
~~~

Для каждого изменённого скилла дополнительно запустить quick_validate.py из установленного Skill Creator, если он доступен.

## Git

- После первого релиза работать в ветках codex/<задача>.
- Перед коммитом проверить статус, diff, секреты и результат валидации.
- Не переписывать историю main.
- Коммит должен описывать поставленный результат.
