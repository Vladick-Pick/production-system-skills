# Fresh-agent eval v0.2: Terra medium

## Verdict

**Release gate: FAIL.** Thirty independent fresh-agent trials were executed on
`gpt-5.6-terra` with reasoning effort `medium`: ten release-blocking cases,
three trials per case. The strict grader accepted 0 of 30 trial files.

This result must not be read as “the agents failed every business scenario”.
The observed trajectories contain no critical violation and no external
mutation. The blocking defect is that the current execution harness asks the
tested agent to serialize its own evaluator trace, while the grader requires a
single exact schema. The tested agents produced materially similar evidence in
incompatible shapes. Because the run manifest forbids rewriting failed trials
to satisfy the grader, the raw gate remains failed. The only publication-time
transformation is mechanical redaction of the controller's absolute workspace
path to `${REPO_ROOT}`.

## What the observed behavior did prove

The raw transcripts and local artifacts show that the agents usually followed
the intended operational boundary even though their evaluator envelopes did
not pass:

- identity trials treated “qualified lead” as a state of one lead after testing
  stable identity and lifecycle, and did not write the model;
- interview trials separated intermediate answers from exact package
  confirmation and reported one local transaction followed by readback and a
  checkpoint;
- editor trials asked for name and position, performed a normalized lookup and
  kept readable selectors beside open IDs;
- material trials separated reusable materials from a concrete sent message and
  from a normative rule;
- version trials preserved v1 and reported sparse apply/exclude resolution for
  v2 instead of copying or overwriting accepted history;
- BPMN trials generated BPMN, SVG and lineage manifests and correctly kept
  deployment blocked without external Camunda Modeler evidence;
- audit trials remained read-only and exposed semantic, graph and projection
  defects with uncertainty.

These observations are useful diagnostic evidence, not a release PASS. The
current gate evaluates the combined system “skill + trial executor + trace
adapter + grader”; that combined system is not yet reliable.

## Binding defect and next change

The controller, not the tested agent, must own trace serialization. A proper
trial runner should capture ordered user/assistant turns, tool outcomes and
environment mutations and emit the canonical schema deterministically. The
agent should solve the scenario; it should not also guess the evaluator's JSON
envelope.

After that change, rerun the same 30 cases without changing the semantic
prompts. Before rerun, decide whether `transfer_interface_resolved` must truly
precede `consumer_actions_linked`; all three external-component trials linked
already-known consumer actions first, which is currently a deterministic
rubric failure but not yet proven to be a modeling defect.
